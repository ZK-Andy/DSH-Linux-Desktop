# 双语契约

本仓库的文档只有中文一份，不启用双语门禁。这一页记的是上游的双语契约与我们的偏离，这样将来真要加英文时不必重新发明规则。

## 我们的现状

所有文档单语中文。`docs/`、`.agents/notes/`、根级文档都没有 `.zh.md` 对照，也没有 `.i18n.yaml` 侧车。`verify-translation-pairing` 与 `verify-md-wrap` 的上游版本都假定存在英中配对，我们没有移植它——移植了也只会空过，空过的门禁看起来绿，实际什么也没断言。

## 上游的契约

上游在 `foo.md` 同目录放 `foo.zh.md` 与 `foo.i18n.yaml`，不设 locale 目录、不交错双语。`.i18n.yaml` 按标题 slug 记录每节的英中哈希，用来回答「这一对在什么内容上确认过一致」。结构必须镜像：标题深度与顺序、列表种类与项数、有序列表起始值、表格行列、链接目标（含 query 与 fragment）、代码块逐字节相同。语言切换器 `English | [中文](foo.zh.md)` 紧跟 H1。

门禁只查哈希与结构，判不了两侧是否真的同义——绿只说明「在这个内容上确认过」，不说明确认得对。这条限制写在契约里，是刻意留的。

## 什么时候启用

只有当某份文档真的需要英文读者时，才为它建三件套，并把 `verify-translation-pairing` 连同它的四个模块一起移植进来。不要为了「对齐上游」先建空配对：没有内容可对照的侧车只会变成需要维护的第二份事实。
