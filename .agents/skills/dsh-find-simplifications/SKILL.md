# 找可简化处

简化 = 删掉代码而行为不减少能力。**不是**把三个函数合成一个更抽象的，也不是换成更短的写法。

## 从哪里找

**补丁里的重复事实。** 同一个路径、同一个版本号、同一个退出码出现在两处以上，就有一处该消失。`patch-surface.sh` 查得到「资源副本」这一类，查不到「同一个常量被抄了两遍」。

**新文件里混进了实现。** 上游文件里成段的逻辑本该在新文件里；反过来，新文件里出现「只为让上游文件少改一行」的转发壳，那是抽象错了。

**脚本之间的搬运。** 一个脚本输出、下一个脚本解析、再下一个脚本又拼回去——中间那层如果没有独立的变化理由，它就是可删的。

**兜底分支。** 每个 `?? default`、`|| fallback`、`catch { return [] }` 都在回答一个真实问题吗？如果答案是「怕它挂」，那不是简化，那是掩盖。

## 判断标准

一次改动碰几个补丁、几个上游文件——这是本仓库唯一的拆分判据（见 [`docs/architecture.md`](../../../docs/architecture.md)）。文件短不短不是判据：AI 让阅读变便宜了，模块可以大到刚好装下一次改动。

## 不要

不要为了「更整洁」重排既有补丁。补丁的边界是历史拼接的结果，重排等于重做别人的试错——除非重排本身能消掉一条规则或一个检查。
