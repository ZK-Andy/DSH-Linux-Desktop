# 文字标准

规则的家在 [`docs/AGENTS.md`](../../../docs/AGENTS.md)（层级、写作规则、字数预算、废话清单）。本技能是把它用在一次具体的写作上。

**这是判据，不是清单。** 逐条打勾会写出正确但读不下去的文字；正确的做法是先写完，再拿这几条回头砍。

## 一句话一条

一段写成一个物理行，不硬折行——折行是渲染器的事。一个段落讲一个意思，讲完就换段。

## 现在时，陈事实

描述已交付的现实用现在时。不写「后来我们改成了」「原先用 X」——那是变更历史，属于提交信息与 Agent Note 的 Alternatives 一节，不属于规格。

## 不写这些

- 会话编号、日期戳、`[x]`/`[ ]` 进度标记、`m03759` 这类引用；
- 实现状态注解（「已实现」「待实现」）——状态由所在的目录表达；
- 手抄的目录树——它会腐烂，需要时用命令生成；
- 强调膨胀：一段里超过一个加粗就砍回去；
- 段落墙：超过六行的段落多半是两个段落。

## 词要具体

「性能问题」不是问题，「首屏从 1.2 秒涨到 4 秒」才是。「若干」「一些」「相关」这类词出现时，问自己具体是几个、哪些、哪方面，写出来或者删掉。

## 一段只干一件事

讲机制的段落别顺手讲历史，讲决定的段落别顺手讲实现细节。写不下去时通常不是文笔问题，是结构上把两件事挤在了一段里——那时该回去看 [`docs/AGENTS.md`](../../../docs/AGENTS.md) 的层级表，看这段内容是不是该放在别处。
