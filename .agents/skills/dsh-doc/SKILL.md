# 文档

## 先决定它住在哪

一个事实只有一个归属，层级表在 [`docs/AGENTS.md`](../../../docs/AGENTS.md)。动手前先回答：这条内容属于常驻指令、架构、计划、决定记录、开发流程、还是对外说明？

答不上来通常意味着它其实该拆成两条，分住两处。

## 各层的边界

- 根 `AGENTS.md`：代理每次都要遵守的指令。一条一到三行，细则链接出去。**不是文档目录**。
- `PLAN.md`：产品规格——需求、构建、分发、更新、打包身份。数值、参数、退出码这类硬事实的家。
- `docs/architecture.md`：形状与边界。为什么这样切、依赖朝哪边流。
- `docs/development.md`：怎么在本地改和验。
- `.agents/notes/`：决定与备选。**不是**现状描述。
- `README.md`：对外说明——是什么、怎么装、怎么用。

## 改完跑门禁

```sh
pnpm run check:all
```

它跑折行、链接、字数预算、Agent Note 结构。字数超了按 [预算一节](../../../docs/AGENTS.md)的顺序处理：先迁走，再压缩，最后才是提高上限。

## 不要

不要为了「完整」补一段背景。读者需要背景时是去读架构文档，不是在你的段落里读一份缩水版。不要在文档里复述代码——代码会变，文档复述的是错的。
